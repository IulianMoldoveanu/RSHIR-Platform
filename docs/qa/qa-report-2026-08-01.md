## §4 Report-Only Findings

### [P1] PR #1022 — demo tenant `is_accepting_orders` not enforced via migration

**File:** `supabase/migrations/**` (no migration present)  
**Finding:** The demo storefront (PR #1007) checks `is_accepting_orders` in application code, but there is no migration that sets this flag to `true` on the demo tenant row in existing production databases. Fresh seeds work; upgraded prod instances may show the demo as "closed."  
**Action required:** Add a migration or seed fixup to ensure the demo tenant row has `is_accepting_orders = true`.

### [P1] PR #1016 — loyalty `unique` index may fail; `search_path` not preserved on definer function

**File:** `supabase/migrations/**`  
**Finding (a):** The unique index on `loyalty_points(customer_id, tenant_id)` added by PR #1016 may fail on prod databases that accumulated duplicate earned rows before the index was introduced.  
**Finding (b):** The `loyalty_earn_on_order()` trigger function is defined with `SECURITY DEFINER` but without an explicit `SET search_path = public`, leaving it vulnerable to search-path injection in untrusted schemas.  
**Action required:** Add `CONCURRENTLY` to the unique index creation with a pre-dedup cleanup step; add `SET search_path = public` to the function definition.

### [P1] PR #1023 — checkout zone/tier `ORDER BY` lacks `id` tie-breaker

**File:** `apps/restaurant-web/src/app/api/checkout/**` (protected — report only)  
**Finding:** The delivery zone/tier selection query sorts by `radius_km ASC` with no secondary sort. When two zones share the same radius, the selected zone is non-deterministic across Postgres plan changes.  
**Action required:** Add `, id ASC` as a tie-breaker to the `ORDER BY` clause.

### [P1] PR #1018 — courier origin check uses `NEXT_PUBLIC_SITE_URL` not set in prod

**File:** `apps/courier/**` (out of scope — report only)  
**Finding:** The courier webhook origin-validation middleware reads `process.env.NEXT_PUBLIC_SITE_URL` for its allowlist, but this variable is not listed in the production deployment env vars. The check silently passes when the env var is absent, nullifying the protection.  
**Action required:** Switch to `COURIER_WEBHOOK_SECRET` HMAC verification or ensure `NEXT_PUBLIC_SITE_URL` is set in all courier deployment targets.

### [P2] PR #1011 — `content_agent_prompts` RLS scoped by `brand_code`, not `tenant_id`

**File:** `supabase/migrations/**` (read-only — report only)  
**Finding:** The RLS policy on `content_agent_prompts` uses `brand_code = current_setting('app.brand_code')` for row filtering. In a multi-tenant deployment where two tenants share a brand code (white-label scenario), each tenant can read the other's prompts.  
**Action required:** Add a `tenant_id` column and update the RLS policy to include `AND tenant_id = current_setting('app.tenant_id')::uuid`.

### [P2] Duplicate Supabase migration filename prefixes (carry-over)

**Status:** Carry-over from previous runs; no new duplicates this cycle.
