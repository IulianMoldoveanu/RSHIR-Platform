### [P2] Several `<img>` tags missing `width`/`height` HTML attributes (CLS risk — CSS-mitigated)

- **Where** `apps/restaurant-web/src/components/storefront/tenant-header.tsx:147`, `demo-storefront/page.tsx:42,85`, `components/marketing/hero-showcase.tsx:71`, `components/marketing/hero-phone-mockup-screen.tsx:98`, `demo-storefront/_components/demo-cart-button.tsx:112`, `apps/restaurant-admin/src/components/feedback-modal.tsx:280`  
- **Symptom** Next.js `no-img-element` is suppressed with `eslint-disable` on each. Browsers cannot reserve layout space before image loads, risking CLS.  
- **Mitigation in place** All tags are constrained by Tailwind `h-*`/`w-*` classes on the element or its container, so actual CLS impact is minimal  
- **Why not auto-fixed** Dynamic URLs (tenant cover, logo, item images) — correct `width`/`height` values are not statically known; migration to `next/image` is a larger refactor. Previously-resolved instances (#950, #1065, #1073) were genuinely unconstrained.
